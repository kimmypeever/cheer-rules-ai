# Cheer Rules AI

A RAG (Retrieval-Augmented Generation) chatbot that answers skill legality questions based on the IASF/USASF rulebooks.

**Live:** https://cheer-rules-ai.vercel.app

Ask it things like:
- *"Is a basket toss legal at Level 3?"*
- *"What level can I do a helicopter?"*
- *"Can I load to prep without a spotter at Level 1?"*
- *"What tumbling is allowed at Level 2?"*

---

## How it works

```
User question
      │
      ▼
  FastAPI (/ask)
      │
      ├─► Query rewriter     (Gemini 2.5 Flash) — rephrases to rulebook terminology
      ├─► Category classifier (Gemini 2.5 Flash) — STUNTS / TUMBLING / PYRAMIDS / DISMOUNTS / TOSSES
      │
      ▼
  ChromaDB vector store
  (rulebook chunks embedded with gemini-embedding-2)
      │
      ▼
  Answer generator (Gemini 2.5 Flash)
      │
      ▼
  Response + sources + category → frontend
```

The system handles six question types automatically:
- **Skill listing** — "what skills can I do at Level 2?"
- **Single-skill legality** — "is a helicopter legal at Level 4?"
- **Level-by-level breakdown** — "what level can I first do a basket toss?"
- **Multi-step sequences** — "can I sponge up to extension then twist to cradle?"
- **Missing safety role** — "can I do a prep without a spotter?"
- **Definitions** — "what is an inversion?"

**Stack:**
- **Frontend:** Next.js 16 (static export) — Vercel
- **Backend:** FastAPI — Google Cloud Run
- **Vector store:** ChromaDB (persistent, baked into the Docker image)
- **Embeddings:** `gemini-embedding-2`
- **Chat model:** `gemini-2.5-flash`

## Local development

### Prerequisites

- Python 3.12+
- Node.js 18+
- A Gemini API key from [Google AI Studio](https://aistudio.google.com/app/apikey)

### 1. Create a virtual environment

```bash
python -m venv .venv
```

Activate it:
- **Windows:** `.venv\Scripts\Activate.ps1`
- **Mac/Linux:** `source .venv/bin/activate`

```bash
pip install -r requirements.txt
```

### 2. Configure environment variables

Create a `.env` file in the project root:

```
GEMINI_API_KEY=your-key-here
```

### 3. Add rulebook PDFs

Place PDFs in `data/rulebooks/`. The project currently uses:
- `iasf_rules_cheer_25-28_final.pdf` — authoritative IASF rulebook (legality, conditions, citations)
- `All Star & Prep Level Appropriate Skills Chart (1).pdf` — Cheer Canada skill listing by level

### 4. Ingest the rulebooks

```bash
python src/ingest.py
```

This extracts text and tables from the PDFs, chunks them, embeds them with Gemini, and stores them in `vectorstore/`. Only new chunks are processed on subsequent runs.

To wipe and re-ingest everything from scratch:

```bash
python src/ingest.py --reset
```

### 5. Start the API server

```bash
uvicorn api:app --reload
```

Runs at `http://localhost:8000`. Interactive docs at `http://localhost:8000/docs`.

### 6. Start the frontend

```bash
cd frontend
npm install
npm run dev
```

Runs at `http://localhost:3000`.

### Testing the backend directly

```bash
# Command line
python src/retriever.py "Is a basket toss legal at Level 3?"

# curl
curl -X POST http://localhost:8000/ask \
  -H "Content-Type: application/json" \
  -d '{"query": "What level can I do a helicopter?"}'
```

## Adding new rulebooks

1. Drop the new PDF into `data/rulebooks/`
2. Run `python src/ingest.py` (only the new PDF is processed)
3. Rebuild and redeploy the Docker image (see Redeploying below)

If a rulebook replaces an existing one, remove the old PDF first and run `python src/ingest.py --reset` to rebuild from scratch.

## Deployment

### Architecture

```
Vercel (frontend)  ──HTTPS──►  Cloud Run (backend)
                                      │
                               vectorstore/ (baked into Docker image)
                                      │
                               Gemini API (embeddings + chat)
```

The vectorstore is bundled inside the Docker image — no external database is needed.

### Backend — Google Cloud Run

**Build and deploy:**

```powershell
# From the project root
gcloud config set project gen-lang-client-0136283693

gcloud builds submit --tag us-central1-docker.pkg.dev/gen-lang-client-0136283693/cheer-rules/api .

gcloud run deploy cheer-rules-api `
  --image us-central1-docker.pkg.dev/gen-lang-client-0136283693/cheer-rules/api `
  --platform managed `
  --region us-central1 `
  --allow-unauthenticated `
  --set-env-vars "GEMINI_API_KEY=your-key-here,ALLOWED_ORIGIN=https://cheer-rules-ai.vercel.app"
```

Run both commands again any time you change backend code or update the rulebooks.

### Frontend — Vercel

The frontend is connected to this GitHub repo and **auto-deploys on every push to `main`**.

Required environment variable (set in Vercel → Project Settings → Environment Variables):

| Key | Value |
|-----|-------|
| `NEXT_PUBLIC_API_URL` | `https://cheer-rules-api-456274226198.us-central1.run.app` |

This is baked in at build time. If the Cloud Run URL ever changes, update this variable and trigger a redeploy.

## API reference

### `POST /ask`

**Request:**
```json
{ "query": "Is a basket toss legal at Level 3?" }
```

**Response:**
```json
{
  "question": "Is a basket toss legal at Level 3?",
  "search_query": "basket toss legality Level 3 TOSSES",
  "category": "TOSSES",
  "level_group": "standard",
  "answer": "LEGAL\n\nFirst allowed at Level 2.\n\nConditions at Level 3:\n...",
  "sources": [
    { "source": "iasf_rules_cheer_25-28_final.pdf", "page": 21, "score": 0.847 }
  ]
}
```

### `POST /feedback`

**Request:**
```json
{
  "question": "Is a basket toss legal at Level 3?",
  "answer": "LEGAL ...",
  "rating": "good",
  "note": ""
}
```

Appends an entry to `feedback.jsonl` on the server.

---

## Feedback

The UI includes thumbs up/down buttons on every response. Ratings are stored in `feedback.jsonl` with the question, answer, timestamp, and rating.

> **Note:** `feedback.jsonl` lives inside the Cloud Run container and is lost on redeployment. To preserve feedback long-term, download it before redeploying or add a `/feedback/export` endpoint.

## Ingest pipeline details

`src/ingest.py` handles two types of PDF content:

- **Tables** (IASF skill tables) — extracted and formatted as structured text blocks, e.g.:
  ```
  STUNTS — A. GENERAL
  LEVEL 1: …
  LEVEL 2: …
  ```
  Each section becomes its own chunk with `category` and `level_group` metadata for filtered retrieval.

- **Plain text pages** (glossary, general rules) — extracted with two-column support (left then right), then chunked with overlap at rule-boundary patterns (`4.1`, `Article 5`, etc.).

Chunks are deduplicated by MD5 hash of `source:page:section:chunk_index`, so re-running ingest on unchanged PDFs is safe.

## Cost

| Service | Cost |
|---------|------|
| Vercel (frontend) | Free (Hobby plan) |
| Cloud Run (backend) | Free tier: ~2M requests/month; idle time not billed |
| Gemini API | Billed per token — `gemini-2.5-flash` is very cheap at low query volumes |

The main cost driver at scale is Gemini API calls (3 per user query: rewrite + classify + answer). Re-ingestion costs one embedding call per chunk.
